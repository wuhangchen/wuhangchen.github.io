Linux 僵尸进程的产生与处理
Linux
Linux
发布日期:   2020-03-17
作者:   吴杭沉
文章字数:   761
阅读时长:   2 分
阅读次数:  

可能很少有人意识到，一个进程调用 exit 之后，它并非马上就消失，而是留下一个称为僵尸进程（Zombie）的数据结构。在 Linux 进程的几种状态中，僵尸进程非常特殊：它已经放弃了几乎所有内存空间，没有任何可执行代码，也不能被调度，仅仅在进程列表中保留一个位置，记载该进程的退出状态等信息供其他进程收集。除此之外，僵尸进程不再占有任何内存空间。

一、为什么要有僵尸进程

僵尸进程的来由要追溯到 Unix。设计者们设计这个东西，并非闲来无事，而是因为僵尸进程里保存着很多对程序员和系统管理员非常重要的信息：

  • 这个进程是怎么”死亡”的？是正常退出、出现错误，还是被其他进程强制退出？——也就是它的退出码是什么；
  • 这个进程占用的总系统 CPU 时间和总用户 CPU 时间分别是多少；
  • 发生页错误的数目和收到信号的数目。

这些信息都存储在僵尸进程中。试想，如果没有僵尸进程：进程执行了多久我们无从得知，一旦其退出，所有相关信息立刻从系统中清除；等父进程或系统管理员需要这些信息时，就无从获取了。

所以，进程退出后，系统会把该进程的状态变成 Zombie，并留出一段时间等父进程来收集其退出信息——因为父进程可能正忙于别的事情而来不及收集。因此，Zombie 状态表示”进程已退出，正在等待父进程收集信息”。

二、如何清除僵尸进程

Zombie 进程不能用 kill 命令清除，因为进程本身已经退出。如果需要清除这样的进程，有两种途径：

  • 清除它的父进程；
  • 等待较长时间后被内核清除。

由于 Zombie 进程还占着一个进程 ID 号，如果这样的进程很多，不利于系统的进程调度。

三、示例

下面来看一个例子：

#include <stdio.h>
#include <unistd.h>

int main()
{
    pid_t pid;
    pid = fork();
    if (pid < 0) {
        printf("error occurred!\n");
    } else if (pid == 0) {
        exit(0);
    } else {
        sleep(60);
        wait(NULL);
    }
}

编译这个程序：

$ cc zombie.c -o zombie

后台运行程序，以便能够执行下一条命令：

$ ./zombie &
[1] 1217

列出系统内的进程：

$ ps -ax
......
1137 pts/0 S 0:00 -bash
1217 pts/0 S 0:00 ./zombie
1218 pts/0 Z 0:00 [zombie]
1578 pts/0 R 0:00 ps -ax

其中的 “Z” 就是僵尸进程的标志，它表示 1218 号进程现在就是一个僵尸进程。

四、小结

收集 Zombie 进程的信息并终结这些僵尸进程，需要在父进程中使用 waitpid 和 wait 调用。这两者的作用都是收集僵尸进程留下的信息，同时使这个进程彻底消失。
